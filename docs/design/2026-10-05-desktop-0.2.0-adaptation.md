# DSH Desktop 0.2.0-rc.2 适配记录（2026-10-05）

> 分支策略：`web` 分支冻结为 **2.0.0**（面向 `dsh web` / DSH 0.1.x），本 `main` 分支为
> **Desktop 适配线 2.1.0**（面向 DSH Desktop 0.2.0-rc.2）。两条线不再互相合并。

## 0. 怎么拿到"宿主到底要什么"

DSH Desktop 的实现代码打包在 `D:\DeepSeek Harness\resources\app.asar`（Electron asar，121 MB，
PowerShell 不能直接当目录读）。本次用一个 30 行的 asar 读取器（解析 8 字节 pickle 头 + JSON
目录索引，按 `baseOffset + entry.offset` 切片）把 `dsh/` 子树解包到临时目录，再对
`dsh/node_modules/@deepseek-ai/*` 做静态核对。**结论都带 `包:行号` 证据**，不是猜的。

关键事实：`runtime.json` 里 `desktopVersion = 0.2.0-rc.2`，Electron 44 / Node 24.21；
`@deepseek-ai/cordis` 4.0.4、`cordis-plugin-timer` 1.1.6、其余 DSH 包统一 `0.2.0-rc.2`。

## 1. 致命项：装载前的 peer 兼容性 preflight

`dsh-app-boot/lib/index.js:286-313` 的 `evaluatePluginCompatibility`：

```js
for (const [name, range] of Object.entries(manifest.peerDependencies)) {
  if (name !== '@deepseek-ai/dsh' && !name.startsWith('@deepseek-ai/dsh-')) continue
  if (!semver.satisfies(runtimeVersion, range, { includePrerelease: true })) peers[name] = range
}
```

- **只校验 `@deepseek-ai/dsh` 与 `@deepseek-ai/dsh-*`**；`@deepseek-ai/cordis` 不参与。
- 不满足时该插件行被**静默 `disabled`**（`dsh-app-boot/lib/index.js:2057-2099`、`2150-2153`；
  bundle 层不兼容则整包 skip `:930-945`），日志文案见 `:322`。**表现是"插件没装一样"，不报错到界面。**
- semver 实测：`^0.1.0-rc.6` / `~0.1.7` / `^0.1.0` 对 `0.2.0-rc.2` **全为 false**
  （预发布区间上界是 `<0.2.0-0`）。本仓库旧 manifest 的三个 peer 全是 `^0.1.0-rc.6`
  → **在 Desktop 上必然被禁用**。
- 修法：升到 `^0.2.0-rc.2`。生态里的兼容写法是 OR 区间
  （`dsh-notify-me`：`>=0.1.6-alpha.2 <0.2.0-0 || >=0.2.0-rc.1 <0.3.0-0`），本分支只面向 Desktop，
  故直接 `^0.2.0-rc.2`。
- 兜底：profile 的 `compatibility.json` 可写精确版本豁免（`dsh plugin allow-version`），
  但它不改变依赖、只解除拒绝，且 profile 的 `cordis.patch.yml` 里要有 `disabled:false` 之类配合。

## 3. Client 半区：装载契约未变，服务名全部仍在

- `window.__ModuleLoader__.load({id, factory})` 仍成立（`dsh-client-modules/lib/index.js:453-475`，
  浏览器侧接管 `lib/client.js:559-566`）；`id` = 包名，入口取 `exports["./client"]`（`:171-181,718-719`）。
- `dsh.client` 只认 4 个字段：`platform`（**唯一合法值 `"web"`**，非 `web` 静默跳过，`:714`）、
  `inject`、`external`、`immediately`（`:61-75`）。Desktop 无专有取值。
  - 注意 `inject` 的语义是**模块行（包名）预到达**，不是 cordis 服务名（`lib/client.js:656-658`）；
    写服务名是无害 no-op。
- 客户端服务全部存在：`sessions`（`dsh-api-session-controller/lib/client.js:3192`）、
  `connection`（`dsh-client-connection:1477`）、`remote`（`dsh-api-gateway:1595`）、
  `modelDirectories`（`dsh-client-ui-model-selection:365`）、`workspaces`
  （`dsh-api-workspace-controller:389`）、`uiWorkspace`（`dsh-client-ui-workspace:772`）、
  `slots`（**`dsh-client-ui-renderer:1323`**，不是 ui-slots 包）。
- `conversation.session.header.actions` 槽位仍在（kind=`list`、scope=`session`，
  `dsh-cordis-client-runner/lib/client.js:3522-3525`），`{name,id,order,inject}` 选项仍合法

- 被消费的宿主 API 形状未变：`sessions.list.getSnapshot()`、`sessions.binding(id)`、

## 4. 真正会坏的：DOM 契约漂移

- **`data-pane` 属性在 0.2.0 已彻底移除**（全树 0 命中）。插件里
  `[data-pane="sidebar"]` / `[data-pane="conversation"]` 失效，靠 `[class*="sidebarCol"]` /
  `[class*="centerCol"]` 兜底才没断。
- CSS Modules 的 class 片段仍在，但带构建哈希前缀（`BynINW_centerCol`），**只能用 `class*=`**：
  `sidebarCol`/`centerCol`（`dsh-client-ui-layout:83,89,112,335`）、`logoRow`/`newSession`/`panelList`
  （`dsh-client-ui-sidebar:114,115,123,307,354,379`）、`sessionRow`/`projectRow`/`searchResultRow`
  （`dsh-client-ui-workspace:1090,1096,1101`）。`[data-sidebar-collapsed]` 仍在（ui-layout:322）。
- **语义漂移（本次修掉的真 bug）**：`centerCol` 的子节点改由官方 `main` **keyed** slot 决定
  （`dsh-client-ui-layout:117-118`，`entryKey = activePanelId ?? "conversation"`），会话 / 插件 /
  计划面板会**互相替换**。工作台是靠"隐藏 `centerCol` 其余子节点"来接管这一列的，于是：
  点侧栏「插件」不会收起工作台 → 插件管理面板被一直隐藏。
  修法：把宿主面板行 `[class*="panelRow"]` 也纳入"点它就收起工作台"的判定
  （`src/client/index.tsx` 的 `onClickSidebarRow`）。

## 5. Desktop 专有信息

- 渲染进程注入 `globalThis.dshDesktop`（`protocolVersion === 1`），已有 `updates`/`browser`/
  `deviceInfo`/`shortcuts`/`keyboard` 等能力；`"dshDesktop" in globalThis` 是官方桌面判定。
- 解包内**没有 Electron main/preload 源码**（`BrowserWindow|preload|contextIsolation` 全树 0 命中），
  所以"桌面禁用了哪些浏览器能力"**未验证**。
- DSH 自身不用 `Notification` / `showOpenFilePicker` / `showDirectoryPicker`（全树 0 命中），
  文件与目录选择走 host 原语。本插件的桌面通知用浏览器 `Notification`（Electron 渲染进程可用），
  若将来被禁会退化为页内横幅。

## 6. 本次改动

1. `package.json`：版本 `1.13.3 → 2.1.0`；peer 区间 → `^0.2.0-rc.2`（cordis `^4.0.4`）；
   devDeps `cordis-plugin-timer 1.1.6`、`dsh-llm ^0.2.0-rc.2`；`test` 脚本加入客户端冒烟测试。
2. `.npmrc`：`node-linker=hoisted`。Windows 上 pnpm 默认 isolated 布局用 junction，
   而 Node 不对 junction 做 realpath（未开开发者模式时 pnpm 也无法用 symlink），
   传递依赖会 `ERR_MODULE_NOT_FOUND`。hoisted 布局全用真实目录，Linux/macOS 同样可用。
3. `src/client/index.tsx`：把 `panelRow` 纳入"点宿主侧栏行就收起工作台"的判定（§4）。
4. `test/clientBundle.test.mjs`：新增客户端半区冒烟测试——用最小 DOM 替身 + 真实 React
   把 `lib/client.js` 跑起来，断言 bundle id、`{name,inject,apply}` 形状、inject 列表与 0.2.0
   客户端服务名一致、官方槽位注册参数、disposer 可调用。此前客户端**零测试**，
   而 1.13.0 的事故正是这一层。
5. `README.md`：Desktop 安装/开发说明、兼容性边界、版本历史。
